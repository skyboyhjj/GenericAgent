## 一、概述

### 1.1 项目背景

慧惠是基于 GenericAgent (GA) 构建的数字伴侣系统。GA 由复旦大学团队开源，具备"上下文信息密度最大化"架构和五层记忆系统，但技能管理存在以下缺口：无修剪、无整合、无迁移、无更新机制，且结晶触发依赖 LLM 自觉（触发率仅20%）。

### 1.2 设计目标

在 GA 外部构建一套**可观测、可调控、可验证**的技能生命周期管理系统——五行流转引擎，使技能具备"生(木)、克(金)、化(火)、通(土)、变(水)"的完整生命周期。

### 1.3 核心指标

| 指标                 | 目标 | 实际                 |
| -------------------- | ---- | -------------------- |
| 结晶触发率           | ≥90% | ≥90%（硬触发机制）   |
| L0公理违反率         | 0%   | 0%（程序化校验）     |
| 技能注册元数据完整率 | 100% | 100%                 |
| GA核心代码侵入       | 零   | < 60行新增（零修改） |
| 自动化测试           | —    | 431项全部通过        |

## 二、系统架构

### 2.1 五行模块映射

```
木·生 (WoodGrower)      → 技能结晶的确定性触发 + 产物质量校验
火·化 (FireTransformer)  → 相似技能合并，消除冗余
金·克 (MetalRestrainer)  → 健康度评估 + 自动归档衰退技能
水·变 (WaterTransformer) → 技能自动更新（第三期设计）
土·通 (EarthMigrator)    → 跨场景迁移（第三期设计）
```

### 2.2 数据流闭环

```
Agent Loop 结束
  → WoodGrower.auto_trigger() [检查工具调用次数]
    → 注入蒸馏指令 → GA原生蒸馏 → WoodGrower.post_validate()
      → SkillRegistry.register() [元数据入库]
        ↓
  [每周审计] FireTransformer.scan() [三层漏斗相似度检测]
    → FireTransformer.merge() [LLM合并执行]
      → 产物校验(R1-R7) → SkillRegistry更新
        ↓
  [每日审计] MetalRestrainer.evaluate_all() [健康度计算]
    → health < 0.3 → archive() [归档至L4]
        ↓
  RootAuditor [周期调度中枢]
```

### 2.3 与GA的集成方式

| 集成点            | 方式                                            | 改动量 |
| ----------------- | ----------------------------------------------- | ------ |
| agent_loop.py     | Agent Loop结束后调用`WoodGrower.auto_trigger()` | ~30行  |
| tools_schema.json | 新增`crystallize_and_register`工具              | ~20行  |
| ga.py             | 导入五行模块，传入配置                          | ~10行  |

**总改动量 < 60行，零修改已有逻辑。**

## 三、模块实现详情

### 3.1 WoodGrower（木·生增强）

**文件**：`skills/wood_grower.py`（350行）

**核心机制**：

```python
class WoodGrower:
    CONFIG_DEFAULTS = {
        "enabled": True,
        "min_tool_calls": 3,      # 最少工具调用次数
        "post_validate": True,     # 产物校验开关
    }
    
    def auto_trigger(self, turn_history, messages) -> bool:
        """Agent Loop结束后自动注入蒸馏指令"""
        # 1. 统计成功工具调用次数
        # 2. 若 < min_tool_calls，返回False
        # 3. 构造蒸馏指令，追加到messages
        # 4. 返回True
        
    def post_validate(self, sop_path) -> ValidationResult:
        """程序化校验SOP产物质量"""
        # R1: 禁止绝对路径 (正则: [A-Z]:\\ 或 /home/ 或 /Users/)
        # R2: 禁止日期格式 (正则: \d{4}-\d{2}-\d{2})
        # R3: 禁止环境特定值 (/usr/、/opt/、C:\\Users\\)
        # R4: 必须有行动验证引用
```

**设计依据**：GA验证报告证实，LLM结晶触发率仅20%，且唯一触发条件是指令中显式包含"记录下来"。因此采用**硬触发 + 程序化校验**替代**LLM自觉 + 自律**。

### 3.2 SkillRegistry（技能注册表）


**核心操作**：`register()` / `lookup()` / `update_usage()` / `archive()` / `restore()` / `set_emotional_value()`

### 3.3 MetalRestrainer（金·克修剪）

**文件**：`skills/metal_restrainer.py`（370行）

**健康度公式（M-02升级后）**：
```
health = 0.30 × freshness + 0.30 × reliability 
       + 0.15 × complexity_bonus + 0.25 × emotional_value

freshness = exp(-0.02 × days_since_last_use)  # 半衰期~35天
reliability = success_count / use_count
complexity_bonus = min(tool_count / 5, 1.0)
emotional_value = 1.0(白名单) / user_override / 0.5(默认)
```

**归档阈值**：health < 0.3 → 自动归档至 L4 archive/

**关键特性**：
- 白名单技能（`whitelist=True`）永远不会被归档
- 归档可恢复（`restore()` 反悔机制）
- 白名单从配置层迁移至数据层（SkillMeta），支持持久化和用户管理

### 3.4 FireTransformer（火·化整合）

**文件**：`skills/fire_transformer.py`（541行，v1.0 轻量先行版 + v2.0设计）

**三层漏斗相似度检测**：
```
Layer 1: 标签快筛（Jaccard系数） → 过滤 < 0.2
Layer 2: 工具交叉验证（工具调用集重叠度） → 过滤 < 0.3
Layer 3: LLM语义判断 → 综合评分 similarity ≥ 0.7 → 合并
```

**当前状态**：
- v1.0（已交付）：四维度纯程序化相似度计算，`find_similar_pairs()` + `generate_suggestions()`
- v2.0（第二期待交付）：LLM语义判断 + LLM驱动SOP合并 + 拆分回退

### 3.5 RootAuditor（归根审计）

**文件**：`skills/root_auditor.py`（415行）

**审计调度**：
- 每日：触发金·克（健康度评估 + 归档）
- 每周：触发火·化（相似度扫描 + 合并建议）+ 金·克
- 每月：触发水·变 + 土·通（第三期）

## 五、架构哲学

慧惠五行流转引擎的四个核心设计原则：

1. **外挂增强，不改核心**：所有模块在GA外部运行，GA核心零侵入
2. **硬触发 + 硬校验**：关键路径不依赖LLM自觉，程序化保障
3. **成功即记录，筛选后置**：结晶阶段放宽，筛选（克/化）后置
4. **零侵入可回退**：所有模块可通过配置开关独立启停

**"为道日损"的工程表达**：
```
旧范式：依赖LLM自觉 → 触发率20%，产物质量不可控
新范式：程序化硬触发 + 硬校验 → 触发率≥90%，L0违反率0%
```
