## 一、问题分析

### 1.1 旧公式的致命缺陷

金·克（MetalRestrainer）的健康度公式原为纯效率导向：

```
health = 0.4 × freshness + 0.4 × reliability + 0.2 × complexity_bonus
```

三个维度全是功能性指标：

| 维度             | 含义                    | 对数字伴侣的伤害                                          |
| ---------------- | ----------------------- | --------------------------------------------------------- |
| freshness        | 指数衰减，半衰期~35天   | **低频陪伴技能（如"深夜安慰"）半年用一次，新鲜度趋近于0** |
| reliability      | 成功率（无数据默认0.5） | 无法区分"因为失效不用"和"因为低频不用"                    |
| complexity_bonus | 工具调用数/5            | 陪伴类技能工具调用少，天然吃亏                            |

**核心矛盾**：一个"主动问候"技能按旧公式——频率低 + 工具少 + 无成功率数据 → 健康度约0.5 → 35天未触发后降至归档阈值以下 → **被金·克淘汰**。

这与"数字伴侣"定位本质冲突：**低频不等于无用，情感价值无法被使用频率衡量。**

### 1.2 模拟验证

以6个测试技能为输入，新旧公式对比：

| 技能                            | 旧health | 新health | Δ         | 归档风险            |
| ------------------------------- | -------- | -------- | --------- | ------------------- |
| skill_healthy（高频工具）       | 0.86     | 0.80     | -0.06     | —                   |
| skill_stale（90天失效）         | 0.31     | 0.36     | +0.05     | ⚠️→✅                 |
| **低频陪伴技能**（类比）        | **0.30** | **0.47** | **+0.17** | **归档边缘→安全区** |
| skill_to_archive（120天低成功） | 0.23     | 0.28     | +0.05     | 仍归档 ✅            |
| memory_management_sop（白名单） | 1.0      | 1.0      | 0         | 永保护 ✅            |

## 二、修改方案

### 2.1 公式升级

```python
# 修改前（纯效率，3维）
health = 0.4 × freshness + 0.4 × reliability + 0.2 × complexity_bonus

# 修改后（引入情感价值，4维）
health = 0.30 × freshness + 0.30 × reliability 
       + 0.15 × complexity_bonus + 0.25 × emotional_value
```

**权重调整逻辑**：

| 维度            | 旧权重 | 新权重   | 变化原因                                 |
| --------------- | ------ | -------- | ---------------------------------------- |
| freshness       | 0.40   | 0.30     | 降低频率依赖，给情感价值腾空间           |
| reliability     | 0.40   | 0.30     | 同上                                     |
| complexity      | 0.20   | 0.15     | 陪伴类技能工具少，降低惩罚               |
| emotional_value | —      | **0.25** | **新增：非效率维度，保护低频高价值技能** |

### 2.2 emotional_value 取值逻辑

```python
def _get_emotional_value(meta: SkillMeta) -> float:
    if meta.whitelist:
        return 1.0           # 白名单：核心陪伴技能，永不淘汰
    if meta.emotional_value_override is not None:
        return meta.emotional_value_override  # 用户手动标记
    return 0.5               # 默认中性值
```

| 条件                       | emotional_value |
| -------------------------- | --------------- |
| 在白名单中（核心陪伴技能） | 1.0             |
| 用户手动标记为"重要"       | 0.95            |
| 其他技能（默认）           | 0.5             |

### 2.3 SkillMeta 字段扩展

在 `skills/skill_registry.py` 的 `SkillMeta` dataclass 中新增三个字段：

```python
@dataclass
class SkillMeta:
    # ... 现有字段 ...
    
    # M-02 新增：情感价值维度
    emotional_value: float = 0.5          # 0.0~1.0，默认0.5
    whitelist: bool = False               # 白名单标志
    whitelist_reason: str = ""            # 原因，如 "core_companion"
```

同步修改 `to_dict()` / `from_dict()`，保证序列化完整性。缺失字段自动填充默认值（**向后兼容**）。

### 2.4 白名单机制迁移

**从配置层 → 数据层**：

```
旧：白名单硬编码在 MetalRestrainerConfig.whitelist = ("memory_management_sop",)
新：白名单存储在 SkillMeta.whitelist 字段（可持久化、用户可管理）
```

新增 SkillRegistry 辅助方法：
```python
def set_emotional_value(skill_name, value, reason) -> bool:
    """用户标记技能情感价值"""
    
def add_to_whitelist(skill_name, reason) -> bool:
    """添加技能到白名单 —— 情感价值自动=1.0"""
```

## 六、数据迁移策略

```
旧YAML (skill_registry.yaml)
  ↓ load() → SkillMeta.from_dict()
  ↓ 缺失字段自动填充:
  ↓   emotional_value ← 0.5
  ↓   whitelist ← False
  ↓   whitelist_reason ← ""
  ↓ 内存中已有完整字段
  ↓ save() → 新YAML永久包含新字段
```

首次加载旧YAML不报错。白名单技能需手动调用一次 `registry.add_to_whitelist()`。

## 七、核心改动总结

> 健康度从 `0.4+0.4+0.2` 纯效率公式，升级为 `0.30+0.30+0.15+0.25` 四维公式，用 `emotional_value` 保护低频高情感价值技能免于被金·克误删。

这不仅是公式的修改，更是**从"工具思维"到"伴侣思维"的跃迁**——数字伴侣的技能不该像工具箱里的扳手一样被淘汰，而应该像记忆一样被珍视。
