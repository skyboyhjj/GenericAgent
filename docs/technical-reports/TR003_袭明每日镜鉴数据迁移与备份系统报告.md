## 一、系统概述

### 1.1 背景

慧惠数字伴侣系统需要从"袭明每日镜鉴"微信小程序同步用户的修行数据（论语读解记录、P忠恕评分、日常反思等），作为数字伴侣的"感知层"输入。两者运行在不同平台：

| 系统         | 平台          | 数据角色                   |
| ------------ | ------------- | -------------------------- |
| 袭明每日镜鉴 | 微信小程序    | 数据生产者（用户修行前端） |
| 慧惠         | Python/GA框架 | 数据消费者（数字伴侣后端） |

### 1.2 设计目标

1. **可靠同步**：支持离线/在线模式的数据导入
2. **格式蒸馏**：从小程序原始数据提炼洞察
3. **算法版本化**：P忠恕算法升级后旧数据可兼容
4. **零侵入**：不修改GA核心记忆管理逻辑

## 三、核心模块详解

### 3.1 XiMingAdapter — 数据同步适配器

**文件**：`memory/gateway/adapters/ximing_adapter.py`（13KB）

**核心功能**：
```python
class XiMingAdapter:
    """
    从袭明每日镜鉴小程序导入修行数据
    
    支持的数据类型：
    - 每日修行记录（P忠恕评分 + 霍金斯层级）
    - 论语读解记录（五步协同）
    - 事件镜鉴（晨间定志 → AI反馈）
    - 用户画像数据（九型分类）
    """
    
    def import_from_json(self, json_path: str) -> ImportResult:
        """导入JSON格式的导出数据"""
        
    def import_from_api(self, api_endpoint: str) -> ImportResult:
        """通过API直接同步（需网络）"""
        
    def validate_schema(self, data: dict) -> bool:
        """校验数据格式是否符合预期schema"""
        
    def normalize(self, raw_data: dict) -> NormalizedData:
        """标准化：统一时间格式、字段命名、编码"""
```

**三种导入模式**：

| 模式         | 触发方式                         | 适用场景           |
| ------------ | -------------------------------- | ------------------ |
| 手动JSON导入 | 用户导出小程序数据→放入指定目录  | 离线环境、隐私优先 |
| API同步      | 小程序云端 → 慧惠本地            | 实时同步、自动化   |
| 增量同步     | 记录上次同步时间戳，仅导入新数据 | 减少重复处理       |

### 3.2 FormulaRegistry — 算法版本控制

**文件**：`memory/gateway/formula_registry.py`

**背景**：P忠恕算法从v1.0（标准加权）优化至v2.0（直觉版/道家版），旧数据的P忠恕分数可能无法与新算法直接比较。

**核心功能**：
```python
class FormulaRegistry:
    """
    管理P忠恕算法的版本演化和旧数据兼容
    
    核心原则：旧数据不过时、版本可追溯、回退可执行
    """
    
    def register_version(self, version_id: str, 
                         weights: dict, 
                         description: str) -> None:
        """注册新版本的算法配置"""
        
    def migrate_score(self, old_score: float, 
                      from_version: str, 
                      to_version: str) -> float:
        """将旧版本分数映射到新版本"""
        
    def get_active_version(self) -> str:
        """获取当前激活的算法版本"""
```

**版本历史**：
| 版本      | 权重 (T/S/C/R)           | 发布日期   |
| --------- | ------------------------ | ---------- |
| v1.0      | (0.20, 0.20, 0.30, 0.30) | 2026-04-09 |
| v2.0-直觉 | (0.15, 0.15, 0.40, 0.30) | 2026-05-01 |
| v2.0-道家 | (0.10, 0.10, 0.50, 0.30) | 2026-05-01 |

### 3.3 XiMingPipeline — 四层蒸馏管道

**文件**：`memory/ximing_pipeline.py`

**设计哲学**："从数据到洞察"——不是简单搬运，而是层层提炼。

```
第一层：事件层 (Event Layer)
  原始事件 → 去重 → 时间序列整理
  
第二层：模式层 (Pattern Layer)
  多个事件 → 频率分析 → 模式识别
  
第三层：洞察层 (Insight Layer)
  模式 + 上下文 → LLM生成洞察
  
第四层：建议层 (Recommendation Layer)
  洞察 → 个性化行动建议
```

**代码结构**：
```python
class XiMingPipeline:
    def distill(self, raw_data: NormalizedData) -> DistillationResult:
        """
        四层蒸馏主流程：
        1. extract_events()    → 事件提取与清洗
        2. detect_patterns()   → 模式识别（频率/趋势/关联）
        3. generate_insights() → LLM驱动的洞察生成
        4. formulate_advice()  → 个性化建议生成
        """
```

### 3.4 MemoryCore L2 — GA记忆对接

**文件**：`memory/memory_core.py`

将蒸馏结果写入GA的五层记忆系统：
- L1索引更新：关键词和主题索引
- L2事实存储：具体修行数据和洞察
- L3技能关联：关联到相关的SOP技能
- 版本标签：标记数据对应的算法版本

### 4.2 备份机制

| 备份类型 | 触发条件                 | 存储位置                     |
| -------- | ------------------------ | ---------------------------- |
| 增量备份 | 每次同步后               | `memory/backup/incremental/` |
| 快照备份 | 每周日                   | `memory/backup/snapshots/`   |
| 归档备份 | 每月1日 + 算法版本更新前 | `memory/backup/archives/`    |
| 手动备份 | 用户触发                 | `memory/backup/manual/`      |

### 4.3 数据一致性保障

| 机制     | 说明                                   |
| -------- | -------------------------------------- |
| 校验和   | 每次同步后计算数据校验和，与源数据比对 |
| 版本标记 | 每条记录标记算法版本号，确保可追溯     |
| 幂等同步 | 相同数据多次导入不产生重复记录         |
| 回滚机制 | 同步失败时自动回滚到上一个一致性检查点 |

## 六、数据隐私与安全

### 6.1 设计原则

| 原则       | 实现                           |
| ---------- | ------------------------------ |
| 本地优先   | 默认JSON离线导入，不上传云端   |
| 用户可控   | 数据清空、导出、删除权限归用户 |
| 最小采集   | 仅导入修行直接相关数据         |
| 透明可审计 | 所有数据操作记录在同步日志中   |

### 6.2 数据生命周期

```
采集（小程序端用户自愿记录）
  → 导出（用户主动操作）
    → 导入（慧惠端适配器）
      → 蒸馏（管道处理）
        → 存储（GA记忆系统）
          → 归档（超过保留期或用户请求删除）
```
