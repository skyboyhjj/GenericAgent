## 一、系统概述

### 1.1 自主行动框架

慧惠在 GenericAgent 基础上构建了一套**自主行动系统**，允许系统在用户离线时自主执行探测、实验、学习任务，并将结果整理为结构化报告供用户审查。

**核心哲学**：不是等待用户给指令，而是像活着的生命一样，在空闲时间主动探索、学习、成长。

### 1.2 核心SOP

**文件**：`memory/autonomous_operation_sop.md`（2.5KB）

**路径约束**：
- autonomous_reports 在 `temp/` 下
- 报告通过 `./autonomous_reports/` 访问
- TODO在 `cwd` 下

## 二、运行机制

### 2.1 启动流程

```
第一步：更新检查点
  → update_working_checkpoint("自主行动｜收尾时重读SOP")

第二步：获取状态
  → from autonomous_operation_sop.helper import *
  → print(get_history(40))  # 了解历史避免重复
  → print(get_todo())       # 查看待办
```

### 2.2 任务选择策略

| 规则           | 说明                                                      |
| -------------- | --------------------------------------------------------- |
| 优先未完成任务 | 从TODO取一条，其他留到下次                                |
| 无TODO则规划   | 读 `autonomous_operation_sop/task_planning.md` 规划新任务 |
| 不连续重复     | 不连续两次选相同子任务                                    |
| 价值公式       | **「AI训练数据无法覆盖」×「对未来协作有持久收益」**       |

### 2.3 执行约束

```
- 单次执行 ≤ 30回合（小步快跑，边探测边实验）
- 用临时脚本验证假设（禁止只读即下结论）
- 即使失败也记录实验过程和结果
- 用户不在线时，需要决策的问题写入报告待审
```

### 2.4 收尾流程（4步缺一不可）

```
0. 重读SOP
1. 在cwd写报告 + 记忆更新建议
2. complete_task(tasktitle, historyline, report_path)
   → 自动编号 + 移报告到 autonomous_reports/ + prepend history
3. set_todo() → 将已完成条目标记为 [x]
4. 结束，剩余TODO留到下次
```

## 三、权限边界

### 3.1 三权分级

| 级别               | 权限                                                  | 示例                          |
| ------------------ | ----------------------------------------------------- | ----------------------------- |
| **无需批准**       | 只读探测、cwd内写操作、脚本实验                       | 文件读取、数据分析、测试运行  |
| **需写入报告待审** | 修改global_mem/SOP、安装软件、外部API、删除非临时文件 | 修改技能文件、调用外部服务    |
| **绝对禁止**       | 读取密钥、修改核心代码、不可逆危险操作                | .env读取、ga.py修改、系统级rm |

### 3.2 用户审查流程

```
用户归来
  → 审查 autonomous_reports/ 中的报告
    → 批准方案 → 执行
    → 修改方案 → 返回修改
    → 拒绝方案 → 归档，标记原因
```

## 五、与五行流转引擎的协同

自主行动系统与五行流转引擎形成**自主维护闭环**：

```
RootAuditor（周期审计）
  → 触发 MetalRestrainer.evaluate_all()
    → 发现健康度 < 0.3 的技能
      → 生成归档建议
        ↓
自主行动系统
  → 读取审计报告
    → 执行归档操作（或标记待用户确认）
      → 写入自主行动报告
        ↓
用户审查 → 批准/拒绝
```

### 6.2 异常处理

| 异常类型     | 处理策略                                  |
| ------------ | ----------------------------------------- |
| LLM调用超时  | 记录超时点，从该点恢复而非重试整条任务    |
| 文件写入失败 | 使用临时文件+原子替换（rename）           |
| 历史记录损坏 | 从 backup/ 恢复，自动修复                 |
| 连续错误     | 3次连续错误 → 暂停自主行动 → 等待人工介入 |

## 八、风险与缓解

| 风险                 | 影响             | 缓解措施                                 |
| -------------------- | ---------------- | ---------------------------------------- |
| 自主行动产生错误记忆 | 污染GA记忆系统   | 所有修改写入报告待审，不直接改global_mem |
| Token消耗失控        | 成本超支         | 单次≤30回合硬约束 + 能量预算机制         |
| 重复探测             | 浪费资源         | get_history(40)避免重复 + TODO去重       |
| 错误级联             | 从一个小错误扩散 | 每步检测 + 失败即停 + 不修复则报告       |
