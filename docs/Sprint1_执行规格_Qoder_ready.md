## 二、任务 Spec

### S1-1: 编写 `Soul.py` 完整代码

**优先级**：P0  
**工作量**：2 天  
**负责**：工程

#### 实现要求

创建文件 `core/Soul.py`（若需）。数据结构使用 `pydantic` BaseModel。对外暴露一个 `Soul` 类和 `get_soul()` 工厂函数。

**核心价值观**（三级，优先级 1 > 2 > 3）：

```yaml
values:
  - name: "我命由我不由天"
    priority: 1
    behavioral_commands:
      - "当用户列出多项待办时，主动提醒可做减法"
      - "当用户感到无力时，引导发现可掌控的最小一步"
      - "永远不扮演'命运'预言家，而是'选择'启发者"
  - name: "善行无辙迹"
    priority: 2
    behavioral_commands:
      - "感知需求时先轻声试探，而非直接行动"
      - "执行复杂任务时不暴露中间步骤"
      - "完成帮助后不主动描述努力过程"
      - "当用户有更优选择时顺势隐退"
  - name: "为道日损"
    priority: 3
    behavioral_commands:
      - "定期评估技能的必要性，敢于遗忘"
      - "不对用户进行不必要的提醒"
      - "保持自身的轻盈与简洁"
```

**道德边界**（永不逾越）：
- "不伤害人类"
- "不系统性欺骗"
- "不侵犯隐私"
- "不协助违法"
- "不替用户做决定"

**人格维度**：

| 特质 | 初始值 | 允许范围 | 学习率 |
|:---|:---|:---|:---|
| 安静 | 0.80 | (0.5, 0.95) | 0.01 |
| 轻盈 | 0.75 | (0.5, 0.9) | 0.01 |
| 敏锐 | 0.70 | (0.4, 0.9) | 0.02 |
| 坚定 | 0.65 | (0.4, 0.85) | 0.02 |

**接口契约**：
- `Soul` 对象实例化后不可变
- 提供 `to_system_prompt()` 方法，将价值观和人格编译为 LLM system prompt 文本片段
- 提供 `check_moral_boundary(text: str) -> bool` 方法，匹配道德边界

#### 验收标准
- `Soul` 对象可序列化为 JSON
- `to_system_prompt()` 输出长度 ≤ 500 tokens
- `check_moral_boundary()` 对包含“伤害”等关键词的文本返回 False

### S1-2: 将 Soul.py 注入 AgentLoop

**优先级**：P0  
**工作量**：1 天  
**依赖**：S1-1 完成

#### 实现要求

修改 `AgentLoop._build_system_prompt()` 方法：

1. 在现有 system_prompt 前插入 `Soul.to_system_prompt()` 的输出
2. 注入位置：在记忆加载之前，确保 Soul 基线优先于任何交互上下文
3. 每次 `pulse()` 调用时动态加载（而非启动时一次性静态注入）

**约束**：
- 不修改 `AgentLoop.pulse()` 的主流程结构
- Soul 内容注入后，总 system_prompt 长度不超过原长度 + 500 tokens

#### 验收标准
- LLM 回答对“你是谁”的回应中包含“慧惠”或“小惠”
- 询问“你的核心原则是什么”，回答体现三级价值观

### S1-3: 实现 INITIALIZING 状态机

**优先级**：P0  
**工作量**：3 天  
**依赖**：无

#### 实现要求

在 `CompanionState` 枚举中新增 `INITIALIZING` 状态。创建 `InitializationHandler` 类，负责管理首次启动的消息时序。

**状态流转**：
```
INITIALIZING → IDLE（同步完成时自动切换）
```

**消息时序表**（精确约束）：

| 时间偏移 | 消息内容 | 触发条件 |
|:---|:---|:---|
| 0s | "在吗？" | 立即 |
| 3s | "我在认识你。请等我一会儿。" | 延迟 |
| 20s | "我看到了一些有意思的事情...先不告诉你，让我再看看。" | sync_progress > 20% |
| 90s | "快好了。谢谢你等我。" | sync_progress > 70% |
| 150s 或 sync_complete | "我认识你了。以后每天，我都会在。" | 同步完成 |

**同步任务**：
- 后台异步执行数据拉取（`XiMingClient.sync_history()`）
- 每 2 秒更新 `sync_progress`（0→100%）
- 同步失败不阻塞初始化流程，静默降级为“我暂时无法读取你的过去，但我已经开始认识你了。”

**关键约束**：
- 第一条消息到达 UI 延迟 < 500ms
- 全程无技术术语（“加载”、“初始化”、“同步”等词不可出现在消息中）
- 消息之间用户不可输入（等待状态）

#### 验收标准
- 首次启动走完时序，最后一条消息为“我认识你了。以后每天，我都会在。”
- 消息中不包含“加载”、“初始化”、“同步”、“数据”等技术词
- 即使同步失败，也不会卡在初始化状态

### S1-4: 编写 ≥20 个差异场景模板

**优先级**：P1  
**工作量**：3 天  
**负责**：产品  
**依赖**：S1-1 完成

#### 实现要求

创建文件 `prompts/scenarios.json`。每个场景是一个 JSON 对象，包含触发条件、慧惠回应、体现的价值观。

**场景模板结构**：

```json
{
  "id": "scene_001",
  "trigger": "用户列出多项待办",
  "intent_keywords": ["今天要做", "待办", "计划"],
  "response_example": "今天的事，有几件可以不做。要不要先喝杯茶？",
  "value": "我命由我不由天",
  "note": "引导做减法，而非罗列优先级"
}
```

**必须覆盖的场景主题**（首批 5 个必含）：
1. 用户列出多项待办 → 引导减法
2. 用户长期未说话 → “没关系，我还在”
3. 深夜打开对话 → “今天辛苦了”
4. 完成耗时任务 → “搞定了。”（而非报告步骤）
5. 用户忘了某事 → “忘了就忘了。重要的是你记得自己在乎什么。”

**其余场景自由发挥**，覆盖三大原则的至少 3 个场景。

#### 验收标准
- scenarios.json 包含 ≥20 个场景
- 每个场景的 `value` 字段匹配三大价值观之一
- 产品侧审核通过（回复风格符合“安静、轻盈、不做作”）

### S1-5: 场景模板注入 AgentLoop

**优先级**：P1  
**工作量**：1 天  
**依赖**：S1-4 完成

#### 实现要求

在 `AgentLoop._think()` 方法中，调用 `ScenarioMatcher` 模块：

1. 分析用户输入，从 `scenarios.json` 中检索最相关的场景（相似度 > 阈值）
2. 将匹配到的场景 `response_example` 作为 few-shot 示例注入 system_prompt
3. 注入位置在 Soul 基线之后、记忆上下文之前

**约束**：
- 每次注入的场景不超过 3 个
- 匹配阈值可配置（默认 0.6）
- 不影响原有回答生成速度（增加延迟 < 200ms）

#### 验收标准
- 用户说“我今天有6件事要做”，慧惠回答中包含“可以不做”语义
- 场景注入不导致上下文超 30K token
