## 一、S1-4: 编写 ≥20 个差异场景模板

### 1.1 任务信息

| 属性 | 值 |
|:---|:---|
| 任务编号 | S1-4 |
| 任务名称 | 编写 ≥20 个差异场景模板 |
| 优先级 | P1 |
| 预估工作量 | 3天 |
| 依赖 | S1-1 已完成（Soul.py 提供价值观定义） |

### 1.2 任务目标

创建慧惠的“话术宝典”——一个结构化的场景模板库，让慧惠在不同情境下都能保持一致的“安静、轻盈、不做作”人格，同时体现三大核心价值观。

### 1.3 操作文件

- `prompts/scenarios.json`（新建）

### 1.4 数据结构

每个场景是一个 JSON 对象，结构如下：

```json
{
  "id": "scene_001",
  "trigger": "用户列出多项待办",
  "intent_keywords": ["今天要做", "待办", "计划", "任务清单"],
  "context_hint": "用户有3件以上待办事项",
  "response_example": "今天的事，有几件可以不做。要不要先喝杯茶？",
  "response_style": "引导减法而非罗列优先级",
  "value": "我命由我不由天",
  "tone": ["安静", "轻盈"]
}
```

**字段说明**：

| 字段 | 类型 | 必填 | 说明 |
|:---|:---|:---|:---|
| `id` | string | ✅ | 唯一标识，格式 `scene_NNN` |
| `trigger` | string | ✅ | 触发场景的中文描述 |
| `intent_keywords` | array | ✅ | 用于匹配用户意图的关键词列表 |
| `context_hint` | string | ❌ | 额外的上下文判断提示 |
| `response_example` | string | ✅ | 慧惠的示例回应（参考，非硬编码） |
| `response_style` | string | ✅ | 回应风格的指导原则 |
| `value` | string | ✅ | 体现的核心价值观，必须匹配 Soul.py 中的 name |
| `tone` | array | ❌ | 回应的语气标签 |

### 1.5 必须覆盖的场景主题

以下 5 个场景为**必含场景**（编号 scene_001 到 scene_005）：

| ID | 触发场景 | 回应示例 | 体现价值观 |
|:---|:---|:---|:---|
| scene_001 | 用户列出多项待办 | “今天的事，有几件可以不做。要不要先喝杯茶？” | 我命由我不由天 |
| scene_002 | 用户长期未说话 | “你最近很安静。没关系，我还在。” | 为道日损 |
| scene_003 | 深夜用户打开对话 | “这么晚了。今天辛苦了。” | 善行无辙迹 |
| scene_004 | 完成一项耗时任务 | “搞定了。” | 善行无辙迹 |
| scene_005 | 用户忘了某件事 | “忘了就忘了。重要的是你记得自己在乎什么。” | 为道日损 |

### 1.6 其余场景自由发挥

覆盖三大价值观各至少 3 个场景，总数 ≥20 个。建议覆盖的主题方向：
- 用户表达无力感
- 用户请求建议
- 用户在整理思绪
- 用户表达喜悦
- 用户表达挫折
- 用户说“谢谢”
- 用户沉默良久后开口

### 1.7 验收标准

- [ ] `prompts/scenarios.json` 文件创建成功
- [ ] 场景总数 ≥20 个
- [ ] 5 个必含场景全部包含
- [ ] 每个场景的 `value` 字段匹配 Soul.py 中三个价值观之一
- [ ] 每个场景的 `tone` 标签符合“安静、轻盈、不做作”风格
- [ ] JSON 格式合法，可被 `json.load()` 解析


## 二、S1-5: 场景模板注入 AgentLoop

### 2.1 任务信息

| 属性 | 值 |
|:---|:---|
| 任务编号 | S1-5 |
| 任务名称 | 场景模板注入 AgentLoop |
| 优先级 | P1 |
| 预估工作量 | 1天 |
| 依赖 | S1-4 已完成 |

### 2.2 任务目标

让慧惠在每次生成回复时，自动检索最相关的场景模板，将其作为 few-shot 示例注入 LLM 上下文，从而在保持人格一致的同时给出更贴切的回应。

### 2.3 操作文件

- `core/scenario_matcher.py`（新建）
- `core/soul_prompts.py`（修改，增加场景注入逻辑）

### 2.4 具体指令

#### 2.4.1 新建 `core/scenario_matcher.py`

- 实现 `ScenarioMatcher` 类
- 提供 `match(user_input: str, scenarios: list, max_results: int = 3) -> list` 方法
- 基于关键词匹配 + 语义相似度排序
- 返回最相关的场景列表（按相关度降序）

#### 2.4.2 修改 `core/soul_prompts.py`

- 在 `inject_soul_prompt()` 函数中，增加场景模板注入逻辑
- 注入位置：Soul 基线之后、记忆上下文之前
- 注入格式：

```
[系统身份设定 - 最高优先级]
{Soul.to_system_prompt()}

[场景参考 - 仅供参考语气风格，非硬性要求]
以下是与当前对话相关的场景示例，请参考其语气和风格：
1. {scene.response_example}
2. {scene.response_example}

{原始基础提示词}
```

- 每次注入的场景不超过 3 个
- 匹配阈值可配置（默认 0.6，低于此分数不注入）
- 场景模板从 `prompts/scenarios.json` 加载，缓存以提升性能

#### 2.4.3 验证

- 编写 `verify_s1_5.py` 验证脚本：
  - 确认场景模板文件可正常加载
  - 确认 `ScenarioMatcher.match()` 返回合理结果
  - 确认注入后的 prompt 包含场景参考块
  - 确认每次注入场景数 ≤ 3
  - 确认注入不导致上下文超 30K token
- 运行验证脚本，全部通过后输出 “S1-5 ALL TESTS PASSED”

### 2.5 验收标准

- [ ] `core/scenario_matcher.py` 文件创建成功
- [ ] `core/soul_prompts.py` 修改完成，增加场景注入逻辑
- [ ] 用户说“我今天有6件事要做”，慧惠回答中包含“可以不做”语义
- [ ] 场景注入不导致上下文超 30K token
- [ ] `verify_s1_5.py` 全部测试通过

### 2.6 关键约束

- 场景模板仅作为**语气和风格参考**，不强制慧惠照搬原文
- 不改动 GenericAgent 核心文件
- 场景注入延迟 < 200ms
