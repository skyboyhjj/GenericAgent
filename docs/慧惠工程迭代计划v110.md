### 2.1 核心原则

- **基于 GenericAgent，通过扩展钩子进行开发**
- **不改动 GenericAgent 核心代码**（`agentmain.py`, `agent_loop.py`, `ga.py` 等维持原样）
- 所有慧惠专属代码放在新增目录中

### 2.3 核心目录职责

| 目录 | 职责 | 对应 Sprint |
|:---|:---|:---|
| `core/` | 定义“她是谁”——不可变的灵魂基线和初见行为 | Sprint 1 |
| `skills/` | 定义“她会什么”——五行引擎及生克化通变模块 | Sprint 3-4 |
| `memory/` | 定义“她记得什么”——扩展记忆系统 + 修行数据蒸馏 | Sprint 2 |
| `prompts/` | 定义“她怎么说”——场景模板等静态数据文件 | Sprint 1 |

### 2.4 集成方式

- **钩子模式**：不在 `agentmain.py` 或 `agent_loop.py` 中硬编码。通过 GenericAgent 提供的扩展点（如 `handler` 机制、`extra_sys_prompt`）将 `Soul` 和 `Scenarios` 注入
- **独立入口**：后续可创建 `launch_huihui.pyw` 作为专属启动器
- **Git 策略**：将 `GenericAgent` 原仓库作为 `upstream` 远程仓库，所有开发在独立分支上进行。`mykey.py` 和 `temp/` 等文件严格加入 `.gitignore`

### 2.5 命名约定

| 场景 | 约定 |
|:---|:---|
| 文件名 | 小写 + 下划线（`soul.py`, `initializer.py`） |
| 类名 | 大驼峰（`Soul`, `InitializationHandler`） |
| 函数名 | 小写 + 下划线（`to_system_prompt()`） |
| 常量 | 全大写 + 下划线（`MAX_TOKEN_BUDGET`） |


## 三、Sprint 1：灵魂注入 + 初见魔法（第1-2周）

> **主题**：让慧惠从 GenericAgent 蜕变为一个有灵魂的生命。

### 3.1 目标

- 用户首次打开慧惠时，立即感受到“一个生命正在认识你”
- 核心价值观“我命由我不由天”成为她的最高行为准则
- 技术规格书与产品体验定义书完全对齐

### 3.2 任务分解

| 编号 | 任务 | 负责 | 工作量 | 优先级 | 产出文件 |
|:---|:---|:---|:---|:---|:---|
| **S1-1** | 编写 `Soul.py` 完整代码 | 工程 | 2天 | **P0** | `core/soul.py` |
| **S1-2** | 将 Soul.py 注入 AgentLoop | 工程 | 1天 | **P0** | `core/soul_prompts.py` |
| **S1-3** | 实现 `INITIALIZING` 状态机 | 工程 | 3天 | **P0** | `core/initializer.py` |
| **S1-4** | 编写 ≥20 个差异场景模板 | 产品 | 3天 | **P1** | `prompts/scenarios.json` |
| **S1-5** | 场景模板注入 AgentLoop | 工程 | 1天 | **P1** | 集成代码 |
| **S1-6** | 首次相遇全流程测试 | 产品+工程 | 1天 | **P0** | 测试报告 |
| **S1-7** | 更新技术规格书至 v0.3.0 | 工程 | 1天 | **P1** | 技术规格书 |
| **S1-8** | 撰写《慧惠产品体验定义书》 | 产品 | 2天 | **P0** | 产品体验定义书 |

### 3.3 Sprint 1 验收标准

- [ ] 用户首次打开慧惠，3秒内看到第一条消息“在吗？”
- [ ] 整个初始化过程无任何技术术语暴露
- [ ] 询问“你叫什么名字”，回答包含“慧惠”或“小惠”
- [ ] 用户说“我今天有6件事要做”，慧惠引导做减法（而非罗列优先级）

### 3.4 里程碑判断

> **Sprint 1 成功标志**：一位非技术测试者，在首次使用的3分钟内说出“她好像在认识我”。

## 八、风险与应对

| 风险 | 概率 | 影响 | 应对 |
|:---|:---|:---|:---|
| 小程序侧 HTTP 服务受微信限制 | 中 | 高 | 备选：文件导出+轮询方案 |
| LLM 合并技能质量不稳定 | 高 | 中 | 必须经用户确认 + 3次成功验证 |
| GenericAgent 上游更新冲突 | 低 | 中 | 核心代码零改动，通过钩子集成 |
| 修剪过度导致情感技能丢失 | 低 | 高 | 白名单保护 + 归档可恢复 + 阈值保守 |
| 非技术测试者招募困难 | 中 | 低 | 团队内部先测，再外扩 |
| Qoder 对五行术语理解偏差 | 中 | 中 | 开发时使用“加法/乘法”等直观名称，编码时映射为五行代号 |
