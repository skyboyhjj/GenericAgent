## S1-3: 实现 INITIALIZING 状态机

**任务编号**：S1-3  
**任务名称**：实现初始化状态机  
**优先级**：P0  
**预估工作量**：3天  
**依赖**：S1-2 完成后可更好地集成验证

### 任务目标
用户首次打开慧惠时，立即激活“初见”仪式。系统以精确时序逐条推送消息，后台静默完成数据同步，全程无技术术语暴露。

### 操作文件
- `core/initializer.py`（新建）
- 新增 `launch_huihui.pyw` 启动入口（新建）

### 具体指令

#### 1. 新建 `core/initializer.py`
- 实现 `InitializationHandler` 类
- 管理 `INITIALIZING` 状态，消息时序如表：

| 时间偏移 | 消息内容 | 触发条件 |
|:---|:---|:---|
| 0s | “在吗？” | 立即（延迟 < 500ms） |
| 3s | “我在认识你。请等我一会儿。” | 延迟 |
| 20s | “我看到了一些有意思的事情...先不告诉你，让我再看看。” | sync_progress > 20% |
| 90s | “快好了。谢谢你等我。” | sync_progress > 70% |
| 150s 或 sync_complete | “我认识你了。以后每天，我都会在。” | 同步完成 |

- `start(sync_func)` 方法启动后台同步，返回异步生成器逐条产出消息
- 同步失败不卡死初始化，降级消息：“我暂时无法读取你的过去，但我已经开始认识你了。”
- 同步完成后状态自动切为 `IDLE`

#### 2. 新建 `launch_huihui.pyw` 启动入口
- 检测是否为首次启动（检查本地标志文件 `huihui_initialized.flag`）
- 若首次启动：进入 `InitializationHandler` 流程，逐条显示消息后进入常规 AgentLoop
- 若非首次启动：直接进入常规 AgentLoop
- 启动完成后创建或更新标志文件

#### 3. 验证
- 编写 `verify_s1_3.py` 验证脚本：
  - 模拟首次启动，验证消息时序（0s/3s/20s/90s/完成）
  - 确认消息中无“加载”、“初始化”、“同步”等禁用词
  - 确认同步失败时触发降级消息
  - 模拟非首次启动，直接进入 AgentLoop
- 运行验证脚本，全部通过后输出 “S1-3 ALL TESTS PASSED”

### 验收标准
- 首次启动，第一条消息在 0.5s 内出现
- 所有消息无技术术语暴露
- 同步成功：最后一条消息“我认识你了。以后每天，我都会在。”
- 同步失败：降级消息触发，流程不卡死
- 非首次启动：直接进入正常对话
