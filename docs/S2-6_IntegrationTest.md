## 五、测试场景

### 场景 1：全链路离线模拟（核心）

模拟完整的数据流，不依赖真实小程序。

1. 加载模拟历史数据（`sample_history.json`，含 7 天、每天 3-5 条事件）
2. 初始化 `XiMingPipeline`
3. 调用 `process_history()` 处理全量数据
4. 验证 `L2Metrics` 包含正确的修行天数、四维均值、阴阳画像
5. 初始化 `MemoryCore`
6. 调用 `update_from_metrics()` 写入 L2
7. 调用 `get_l2_context()` 检索 L2 画像
8. 验证 L2 检索结果非空、包含画像名称、长度 ≤500 tokens

### 场景 2：每日增量处理

1. 加载模拟今日数据（`sample_today.json`）
2. 调用 `process_daily()` 处理单日数据
3. 验证 `DailyInsight` 包含正确的日期、能量曲线、建议
4. 调用 `update_from_daily()` 写入 L1
5. 调用 `get_l1_context()` 检索 L1
6. 验证 L1 检索结果非空、长度 ≤1000 tokens

### 场景 3：记忆注入全流程

1. 使用场景 1 和 2 中已填充的 `MemoryCore`
2. 调用 `inject_soul_prompt(base_prompt, user_input, memory_core)`
3. 验证返回的 prompt 中包含 `[对你的理解]` 段落
4. 验证段中包含综合画像名称（如“笃行的清明者”）
5. 验证不传 `memory_core` 时，`[对你的理解]` 段不出现（向后兼容）

### 场景 4：算法版本兼容性验证

1. 构造两组事件，分别标记 `algorithm_version: "1.0.0"` 和 `"9.9.9"`（未知版本）
2. 验证 `check_compatibility("1.0.0", "1.0.0")` 为 True
3. 验证 `check_compatibility("1.0.0", "9.9.9")` 为 False
4. 验证 `verify_p_score()` 对已知版本正确验证，对未知版本返回 False

### 场景 5：记忆自动修剪

1. 填充 35 条 L1 条目（超过 30 天阈值）
2. 验证 `_prune_l1()` 后 L1 条目数 ≤30
3. 填充 12 个 L2 快照（超过 10 个阈值）
4. 验证 `_prune_l2()` 后 L2 快照数 ≤10

### 场景 6：端到端线程安全与降级

1. 模拟多个感知源同时同步（使用 `DaoGateway.sync_all()`）
2. 单个感知源失败（模拟不可达），验证不阻塞其他源
3. 验证融合引擎正常输出 `MultiModalEventStream`

### 场景 7：Token 预算总控

1. 模拟完整的 prompt 注入流程（Soul 基线 + 场景模板 + 记忆上下文）
2. 验证总 prompt 长度不超过 30K token
3. 验证记忆段独立长度：L1 ≤1000, L2 ≤500, 综合 ≤1500

## 六、模拟数据要求

`sample_history.json`：
- 7 天数据，2026-04-23 至 2026-04-29
- 每天 3-5 条事件
- 四维分数随机但合理（5-9 分之间）
- 包含一个明显的修行趋势（如缘位轴分数逐日上升）
- 包含至少 2 种霍金斯能量层级

`sample_today.json`：
- 当天数据（2026-05-03）
- 包含晨间定志、日间事件、晚间回顾
- 事件数与历史数据有明确关联（如延续上升趋势）
