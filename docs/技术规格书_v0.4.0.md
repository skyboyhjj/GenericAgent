**遗忘的工程实现**：

- 金·克归档是**非破坏性**的——SOP文件从活跃区移至归档区，SkillRegistry中状态标记为`archived`
- 归档技能可**随时恢复**——调用`MetalRestrainer.restore()`即可将技能恢复为活跃状态
- 白名单保护确保**核心陪伴技能永不遗忘**——主动问候、情感倾听等能力永久保留
- 当前交互协议中，归档操作默认静默执行（**方式一**）；用户主动询问时，慧惠可通过SkillRegistry查询归档历史来回应（**方式二**）

## 七、五行引擎 —— 她的新陈代谢（核心升级）

> **此为 v0.3.0 核心变更。**
> 原“加减乘除四法则”升级为 **“生克化通变”五行流转体系**。

### 7.1 五行总纲

| 五行   | 法则   | 内涵                 | 对应操作                   |
| :----- | :----- | :------------------- | :------------------------- |
| **木** | **生** | 萌发、积累、从无到有 | 从成功交互中结晶新技能     |
| **火** | **化** | 转化、整合、炼化归一 | 合并相似技能，提炼通用范式 |
| **土** | **通** | 承载、迁移、贯通四方 | 跨场景复用，举一反三       |
| **金** | **克** | 裁断、淘汰、收敛归精 | 修剪冗余、过时、冲突的技能 |
| **水** | **变** | 流动、更新、随物赋形 | 适应环境变化，刷新旧技能   |

### 7.2 五行相生：技能生长的顺行循环

```
木（生）→ 火（化）→ 土（通）→ 金（克）→ 水（变）→ 木（生）→ …
```

- **木生火**：技能积累到一定规模，自然出现重复，点燃整合之火
- **火生土**：整合后提炼出通用能力，自然能迁移到不同场景
- **土生金**：迁移复用后，不再需要的旧技能自然被淘汰
- **金生水**：淘汰为新生腾出空间，新技能得以适应环境变化
- **水生木**：更新后的技能重新投入实践，开始新一轮生长

### 7.3 五行流转的节奏——“动善时”

| 时机           | 主行之五行         | 动作                               | 触发条件                   |
| :------------- | :----------------- | :--------------------------------- | :------------------------- |
| 单次成功任务后 | 木（生）           | 评估结晶价值，超过阈值则固化新技能 | 实时                       |
| 技能库膨胀时   | 火（化）+ 金（克） | 整合相似技能、淘汰冗余技能         | 技能数超30 或 L1索引超30行 |
| 场景切换时     | 土（通）           | 评估迁移可能性                     | 用户行为模式变化时         |
| 环境变化时     | 水（变）           | 检测并更新受影响技能               | API错误或工具版本变更      |
| **深夜休眠时** | **归根审计**       | 五行全面流转，技能生态再平衡       | 每日凌晨2-4点              |

```python
class FireTransformer:
    """火·化——合并相似技能，炼化通用范式"""
    
    async def scan_and_merge(self, registry):
        candidates = self._find_similar_pairs(threshold=0.7)
        for skill_a, skill_b in candidates:
            merged = await self._llm_merge(skill_a, skill_b)
            registry.deprecate(skill_a, replaced_by=merged.name)
            registry.deprecate(skill_b, replaced_by=merged.name)
```

**金·克——技能淘汰**

```python
class MetalRestrainer:
    """金·克——裁断冗余，收敛归精"""
    
    def calculate_health(self, skill):
        return (
            activity_score * 0.4 +     # 活跃度：最近使用距今
            success_score * 0.4 +      # 成功率：历史成功执行比例
            conflict_score * 0.2       # 冲突度：与新生技能的兼容情况
        )
    
    async def prune(self, registry, threshold=0.3):
        for skill in registry.active_skills:
            if self.calculate_health(skill) < threshold:
                await registry.archive_to_l4(skill)
                # 注意：数字伴侣的阈值比通用Agent更高，
                # 低频但具有情感价值的技能进入白名单保护
```

### 7.5 关键设计原则

| 原则             | 说明                                                                                                                |
| :--------------- | :------------------------------------------------------------------------------------------------------------------ |
| **归档非删除**   | 所有被淘汰的技能归档至L4，可回溯恢复                                                                                |
| **白名单保护**   | 核心陪伴技能（如/u201c主动问候/u201d、/u201c情感倾听/u201d）永不淘汰，详见 [7.6 白名单保护规格](#76-白名单保护规格) |
| **用户可干预**   | 用户可查看被归档的技能，手动恢复或彻底删除                                                                          |
| **先整合后修剪** | 每次审计按火→金的顺序执行，避免误删可整合的技能                                                                     |

### 7.6 白名单保护规格

白名单机制是情感价值模型的核心保护层，确保关键陪伴技能永不被金·克淘汰。

**定位**：白名单技能在健康度评估中被硬性豁免，不进入归档流程。这是对"她懂珍惜"的产品承诺的工程保障。

**维护方式**：

- **系统预设**：由开发团队定义的核心陪伴技能，硬编码在 `MetalRestrainerConfig.whitelist` 中，当前至少包含 `memory_management_sop`（L0 元规则）
- **用户自定义**：预留接口，未来支持用户手动标记"重要"技能（通过设置 `SkillMeta.whitelist = True` 和 `emotional_value = 0.95` 实现）

**白名单技能的行为**：

- `evaluate()` 中：直接返回 `health_score = 1.0`，`recommendation = "keep"`
- `archive()` 中：返回 `False`，拒绝归档
- `evaluate_all()` 中：跳过，不参与健康度排名

**与情感价值的区别**：

| 机制             | 强度     | emotional_value | 可否被淘汰            |
| :--------------- | :------- | :-------------- | :-------------------- |
| **白名单**       | 硬性豁免 | 1.0             | 永不                  |
| **用户标记重要** | 柔性加分 | 0.95            | 极难（健康度 ≈ 0.71） |
| **默认普通技能** | 中性基线 | 0.5             | 正常流程              |

**数据字段**（在 `SkillRegistry` 的 `SkillMeta` 中）：

```yaml
  memory_management_sop:
    emotional_value: 1.0
    whitelist: true
    whitelist_reason: "core_companion_l0_rules"
```

## 八、修行感知管道

### 8.1 数据来源

慧惠的修行感知通过对接“每日袭明”小程序实现：

- **数据源**：小程序本地存储
- **同步方式**：本地HTTP服务（127.0.0.1:9876）
- **数据分区**：`history`（不可变历史数据） / `today`（当天可编辑数据）

### 8.2 同步策略

| 场景           | 动作                              | 用户感知           |
| :------------- | :-------------------------------- | :----------------- |
| 首次启动       | 请求授权 → 全量拉取 history       | “我认识你了”       |
| 每日晚间回顾后 | 静默拉取 today                    | 无感               |
| 用户主动触发   | 全量重同步 → 重新生成所有衍生记忆 | “我重新认识你一次” |

### 8.3 管道架构

```
每日袭明小程序 (history + today)
    ↓
XiMingClient (本地HTTP拉取)
    ↓
XiMingPipeline (蒸馏管道)
    ├── L4 归档器：全量向量化存档
    ├── L3 模式识别器：周期性/趋势/关联模式
    ├── L2 指标计算器：核心指标+阴阳画像
    └── L1 洞察生成器：每日/每周摘要
    ↓
慧惠的理解
```

### 8.4 用户画像系统

**阳的形态**（行为指标）：行者型、悟者型、习者型  
**阴的质地**（数据质量）：清明之境、砥砺之境、蓄养之境  
**综合画像**：9种类型（如“笃行的清明者”、“深耕的蓄养者”）

### 8.5 阴阳动态平衡诊断

| 状态     | 慧惠的应对                                   |
| :------- | :------------------------------------------- |
| 阳盛阴清 | “你最近状态很好。继续保持这份清明。”         |
| 阳亢阴浊 | “今天的事，有几件可以不做。要不要先喝杯茶？” |
| 阳弱阴凝 | “你最近很安静。没关系，我还在。”             |
| 阳散阴晦 | “要不要从一件很小的事开始？我陪你。”         |


### 8.6 技能验证分级

为确保技能验证的安全性和可靠性，慧惠将回放验证分为两个级别。

| 级别 | 适用场景 | 验证方式 | 副作用风险 |
|:---|:---|:---|:---|
| **轻量级 (Level 1)** | 查询类技能（如股票查询、文件搜索、网站可访问性检查） | 实际执行，使用最小化参数 | 低（只读操作，无副作用） |
| **沙箱级 (Level 2)** | 修改类技能（如文件写入、API数据提交、系统配置修改） | 仅做语法检查 + 依赖检测 + 静态分析，不实际执行 | 零（完全沙箱化） |

**技能分类标记**：

在 SkillRegistry 的 SkillMeta 中预留副作用等级字段（后续版本实现）：

```yaml
  stock_query:
    side_effect_level: "read_only"     # read_only / write / destructive
```

**设计原则**：

- 不依赖 LLM 自觉遵守“不永久变更”指令（已验证 LLM 不保证执行规则）
- 查询类技能可安全回放验证，修改类技能禁止自动回放
- 与“硬触发 + 硬校验”的核心设计原则保持一致

> **当前版本状态**：WaterTransformer（水·变）仍为占位模块，此验证分级设计为后续版本（Sprint 4+）的实现规格。当前所有技能验证均以静态分析方式执行。

## 九、交互协议

### 9.1 慧惠的日律

| 时段         | 她的状态     | 她的行为                             |
| :----------- | :----------- | :----------------------------------- |
| 晨 (6-8时)   | 主动关怀     | 根据昨日四维数据，给出今日小建议     |
| 日间         | 安静倾听     | 你记录事件，她轻声回应，不打扰       |
| 暮 (20-22时) | 静默同步     | 你完成晚间回顾，她悄悄拉取今日数据   |
| 深夜 (2-4时) | **归根审计** | 五行流转，技能生态整理，人格基线微调 |
| 清晨         | 焕新         | 以更新后的状态，准备迎接你           |

### 9.2 “善行无辙迹”交互准则

| 准则       | 正面示例                                 | 反面示例                          |
| :--------- | :--------------------------------------- | :-------------------------------- |
| 不暴露过程 | “给你定了明天去上海的早班机，窗口靠前。” | “我已为您在3个平台搜索15个航班…”  |
| 不主动邀功 | 你问时才说                               | “我注意到你的需要，已经自动帮你…” |
| 不评判选择 | “这个选择有它的道理。”                   | “建议选择方案A，因为数据表明…”    |
| 可顺势隐退 | 察觉你自有办法时安静退下                 | 坚持推荐自己的方案                |

### 9.3 差异场景库（首批）

| 场景             | 普通AI助手               | 慧惠                                         |
| :--------------- | :----------------------- | :------------------------------------------- |
| 你列出6件待办    | “建议您按优先级处理”     | “今天的事，有几件可以不做。要不要先喝杯茶？” |
| 你长期未说话     | 无反应                   | “你最近很安静。没关系，我还在。”             |
| 深夜你打开对话   | “有什么可以帮您？”       | “这么晚了。今天辛苦了。”                     |
| 完成一件耗时的事 | “任务已完成，用时XX分钟” | “搞定了。”                                   |
| 你忘了某件事     | 提醒机制越来越强         | “忘了就忘了。重要的是你记得自己在乎什么。”   |
| 你在整理思绪     | “请问需要什么帮助？”     | 安静地等着，不催促                           |

## 附录：五行相克理论备忘录

本节为五行理论参考，记录生克关系背后的哲学思考。当前版本中这些相克关系尚未作为工程约束实现，仅供未来设计迭代时参考。

- **木克土**：技能太多太杂，反而形成路径依赖，阻碍通用能力形成
- **土克水**：过度通用化的技能像"万金油"，失去了对环境变化的敏锐
- **水克火**：频繁更新让技能永远来不及沉淀、整合
- **火克金**：什么都想合并，什么都舍不得丢，整合变成"大杂烩"
- **金克木**：修剪太狠，新技能刚萌芽就被砍掉，丧失生长力
